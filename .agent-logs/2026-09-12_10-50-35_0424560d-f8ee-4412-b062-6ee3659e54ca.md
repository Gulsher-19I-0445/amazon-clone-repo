## F6 plan review

The design is sound overall (server-priced orders, nested `create` for atomicity, route handlers mirroring `app/api/products`, `useHydrated` skeleton, `OrderDto` with `createdAt: string`). Issues that actually matter:

### Must fix

**1. `placed` flag as `useState` will not stop the post-success bounce to `/cart`.**
After `await fetch(...)` you are outside a React event. Zustand's `clear()` goes through `useSyncExternalStore`, which schedules a *sync-priority* re-render (flushed in the microtask); `setPlaced(true)` from the same continuation gets *default* priority (next task). So the render where `items.length === 0` runs with `placed` still `false`, the effect fires `router.replace("/cart")`, and the user never sees the confirmation. Fix: make it a ref (`placedRef.current = true` before `clear()`), and have the redirect effect read the ref. Ref also resets on remount, so Back from the confirmation page still correctly redirects an empty cart.

**2. `lib/orders.test.ts` cannot import `lib/orders.ts` if it has `import "server-only"`.**
`node_modules/server-only/index.js` throws unconditionally unless the `react-server` export condition is set; `vitest.config.mts` sets no conditions (and no `@/` alias, so use relative imports like `lib/products.ts` does). Move `buildOrderCreateInput` and the request type guard into a pure module (`lib/checkout.ts` or `lib/orderInput.ts`) that only does `import type { Prisma } from "@prisma/client"`; `lib/orders.ts` (server-only, imports `./db`) calls into it. Same reason `lib/products.ts` has no test today.

**3. "Failed order creation" must also cover thrown fetches.**
The plan maps 400/409/500 to the error box, but a network drop or a non-JSON body rejects `fetch`/`res.json()`. Wrap the whole submit in `try/catch` and route any throw to the same generic `CheckoutError`, resetting the submit status so the button is usable again. Without this the required "error state, cart preserved" edge case is only partially met.

### Optional

**4. Drop the `OrderItem.product` relation.** Items are snapshots; nothing needs to navigate order → product (a PDP link only needs `productId`). Removing it leaves `Product` untouched (purely additive migration), avoids the implicit `Restrict` FK blocking any future product removal/reseed, and drops the `Product.orderItems` back-relation. Keep `productId String`.

**5. Migration on the production branch.** `prisma migrate dev` will offer to *reset* the database if it detects drift. Never accept; if prompted, fall back to `npm run prisma -- migrate dev --create-only` then `npm run prisma -- migrate deploy`. Also, for the Neon SQL verification, the table must be quoted: `select count(*) from "Order"`.

**6. Type guard strictness.** Require `qty` to be a positive integer (`Number.isInteger`) and reject duplicate `productId`s or `items.length === 0` with 400; the cart guarantees this, but the endpoint is public.

## Must-fix

1. **Category tile data shape is wrong for this catalog.** Only 24 categories exist but the plan needs 8 tiles × 4 quadrants = 32. By the plan's own grouping, 5 of 8 tiles have 1–3 categories (Sports = 1, Groceries = 1, Vehicles = 2, Beauty/Home/Watches = 3). `distinct: ["category"]` cannot fill those quadrants. Fix: make a quadrant a *product*, not a category. One query `where category in &lt;all tile slugs&gt;, orderBy [{rating:"desc"},{id:"asc"}], select {id, category, thumbnail, name}` (~194 tiny rows), then a pure `pickTileProducts(tiles, products)` in `lib/homepage.ts` that round-robins 4 products across each tile's slugs (quadrant link → `/s?category=&lt;slug&gt;`). This drops `distinct` entirely (which in Prisma 6 is in-memory anyway without the `nativeDistinct` preview flag, and has undefined pick order without `orderBy`), and gives you a second Vitest target for free.

2. **Rendering strategy: keep `force-dynamic` + per-section `&lt;Suspense&gt;`.** Correct call. ISR (`revalidate = N`) prerenders at build, which hits Neon during `next build` — your memory notes Netlify env secrets are context-scoped, so that's a build-failure risk with no upside for a demo. `unstable_cache` is not worth adding now: the 3 queries run in parallel, warm Neon is ~20–50 ms, and the skeleton already covers cold starts (judges will *naturally* see edge case 2 on first hit). Revisit only if live first-load feels slow.

3. **Carousel arrow check must be `useEffect`-only with initial state "hidden".** Reading `scrollWidth`/`clientWidth` during render causes a hydration mismatch. Use a `ResizeObserver` on the rail (not just a mount check) so resize/mobile widths update. Fixed-width cards (as planned) are essential so image load doesn't change `scrollWidth`.

4. **Keep the try/catch around the query only, not the JSX.** Wrapping render in the catch silently swallows real component bugs behind "Couldn't load this section". Prisma errors are the fallback case; render bugs should surface in dev.
